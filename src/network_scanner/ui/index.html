    Using IP Scanner

    Keep this guidance open while reviewing or running a scan.

    Run a network scan

    1. Select Scan detected network to use the active adapter and subnet.
    2. Use Scan custom range to provide inclusive starting and ending IPv4 addresses.
    3. Every address in that inclusive range is attempted. Requested and Attempted should match when the scan completes without an interruption.
    4. Wait for the scan to finish before starting another scan, then review the selected entry under Previous network scans.

    Remember: Scan only networks that you own or are authorized to assess.

    Keep results current

    • Manual scans run immediately when you select either scan button.
    • Automatic scans use the detected local network at the interval you select. The installed application must be running.
    • The status beside the controls shows when the latest scan completed and when the next automatic scan is due.
    • Fresh is within one selected interval. Aging is within two intervals. Stale is older than two intervals.
    • Manual and automatic scans share one coordinator, so a second scan cannot start while one is active.

    Understand device results

    • Confirmed devices answered an active check or discovery protocol. Observed devices have only a unique local ARP association.
    • Evidence lists the sources that established presence, including ICMP, TCP, ARP, mDNS, UPnP, and NetBIOS.
    • High confidence uses a discovery identity or multiple active signals. Medium uses one active response. Observed is ARP-only.
    • Role identifies the detected default gateway when applicable.
    • Open services reports selected common services that answered. It is not an exhaustive port scan.

    Why some values are unknown

    • Not advertised means the device did not publish a usable name, manufacturer, or model through the available local sources.
    • Not available means a MAC address could not be established. Routed or isolated devices commonly have this result.
    • Broadcast addresses, invalid MAC addresses, and likely proxy-ARP-only artifacts are attempted but excluded from device totals.
    • IP Scanner reports observed facts and does not guess identity, ownership, or security status.

    Arrange and interpret device results

    • Select any column heading to sort that table. Select it again to reverse the order.
    • Drag the divider at the right edge of a Device Results heading to resize that column. Double-click the divider to restore its original width. Your widths are retained in this browser.
    • With a divider focused, use the Left and Right Arrow keys to resize, or press Home to restore the original width.
    • MAC addresses use uppercase colon-separated formatting.
    • Shared/proxy response means the address was returned for multiple IPs and is not presented as the device's confirmed hardware address.
    • Missing manufacturers are checked against a bundled local IEEE OUI list. Scanned MAC addresses are not sent to an external service.
    • The first Device Results column uses observed evidence to show Router, Computer, Printer, TV, Audio, NAS, Mobile, IoT, or Other. Other is used when the type cannot be established.

    Data and privacy

    • Scan history is stored locally on this computer.
    • The interface is served only on the local loopback address.
    • Clearing history removes the saved scan records from this installation.

    About this baseline

    • This is Ramrattan IP Scanner v1.1.0, the owner-accepted Desktop Application Release.
    • The application runs a local service and opens its interface on this computer. It does not expose the interface to the network.
    • Version 1.1.0 provides manual and scheduled collection in native Intel Mac, Apple silicon Mac, and Windows x64 packages.
    • The published packages are unsigned, so macOS Gatekeeper or Windows SmartScreen may display a warning.
    • All three applications share this interface, discovery behavior, Help, and local data model.

    Resolve common issues

    • No adapter detected: Confirm that Wi-Fi or Ethernet is connected.
    • No devices found: Confirm that the requested range is on the locally connected network. Client isolation can prevent local discovery.
    • Few device names: Confirm that local multicast is allowed. Firewalls, guest networks, and disabled Bonjour, UPnP, or NetBIOS can limit identity details.
    • Old interface after an update: Relaunch the application or refresh the page while holding Shift.
    • Page does not respond: Confirm that the IP Scanner service is still running.
